            return "Горячо!";

## Главные выводы

1. `if/else` — базовая конструкция ветвления, но при большом числе взаимоисключающих вариантов она становится громоздкой.
2. `switch/case` удобнее и читаемее при сравнении одной переменной с несколькими конкретными значениями.
3. Тернарный оператор `? :` сокращает простые `if/else` до одной строки, но ухудшает читаемость, если вложен или содержит сложные выражения.
4. `int.TryParse()` безопаснее `int.Parse()`, потому что не выбрасывает исключение при некорректном вводе.
5. Логические операторы `&&`, `||`, `!` позволяют строить сложные условия без вложенных `if`.

## Ответы на вопросы

**1. Чем `int.TryParse()` безопаснее `int.Parse()`? В каких случаях стоит использовать каждый?**

`int.Parse()` выбрасывает исключение `FormatException`, если строка не является числом. Если её не обработать — программа упадёт. `int.TryParse()` возвращает `bool` (успех/неудача) и записывает результат в `out`-параметр. Использовать `int.Parse()` — когда ввод гарантированно корректный (например, читаем из файла, который мы сами сформировали). `int.TryParse()` — при вводе от пользователя, чтобы не ронять программу.

**2. Когда `switch` удобнее, чем цепочка `if/else if`?**

Когда сравнивается **одна переменная** с **конкретными значениями** (числа, строки, символы), а не диапазоны. Пример из жизни: меню в банкомате — «1 — баланс, 2 — снять, 3 — перевести, 4 — выход». Через `switch` это читается явно, а через `if/else if` — громоздко.

**3. Что произойдёт в `switch`, если убрать `break` после одного из `case`?**

Выполнение «провалится» в следующий `case` и продолжит выполняться до `break` или конца блока. Это называется **fall-through**. В C# это **запрещено**, если `case` содержит исполняемый код — компилятор выдаст ошибку. Исключение: пустые `case` подряд (как в сезонах — `case 12: case 1: case 2:`) — там fall-through допустим.

**4. Чем отличается `=` от `==` в C#? Почему это частая ошибка?**

- `=` — **присваивание**: `x = 5` кладёт значение 5 в переменную `x`.
- `==` — **сравнение**: `x == 5` возвращает `true`, если `x` равен 5.

Частая ошибка потому, что в математике «равно» обозначается одним `=`, а в C# это уже занято присваиванием. В условии `if (x = 5)` компилятор выдаст ошибку, потому что результат присваивания — число, а не `bool`. Но в некоторых языках (C, JavaScript) это молча даёт `true` — отсюда привычка ошибаться.

**5. Можно ли написать тернарный оператор внутри другого тернарного оператора?**

Да, можно, но читаемость сильно страдает. В лабораторной использовала один тернарный оператор:

```csharp
string result = attempts <= 7
    ? $"Отличный результат! Всего {attempts} попыток."
    : $"Число найдено за {attempts} попыток. Можно лучше!";
```

Вложенный тернарный выглядел бы так:

```csharp
string level = attempts <= 3 ? "Профи"
             : attempts <= 7 ? "Хорошо"
             : attempts <= 15 ? "Средне"
             : "Слабо";
```

Читается тяжело, лучше заменить на `if/else if` или `switch`.
